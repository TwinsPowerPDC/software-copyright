# 设计文档（软件说明书）写作规范

本文档为软著申请中"设计文档（软件说明书）"的详细写作指南，基于真实申请材料分析整理。

---

## 一、整体格式要求

| 项目 | 规范 |
|------|------|
| 文档形式 | 结构化设计文档（非叙述性文章） |
| 表格占比 | 约 40-60%，多用表格少用长段落 |
| 业务对象标记 | 使用【】标记，如【订单】、【用户账户】 |
| 枚举值格式 | `0:未开始 1:进行中 2:已完成` |
| 字数目标 | 不强制字数，章节完整性优先 |
| 语言风格 | 客观、简洁、准确，避免营销性措辞 |
| 最终格式 | Word 文档（.docx）提交 |

---

## 二、章节模板

### 第一章 需求背景

**写作要点**：
- 说明系统建设的背景和必要性
- 描述目标用户群体和核心业务场景
- 概述系统解决的核心问题

**参考结构**：

```
随着[行业/业务]的发展，[目标用户]在[业务场景]中面临以下挑战：
[挑战1]、[挑战2]、[挑战3]。

本系统旨在为[目标用户]提供[核心功能]，实现[业务目标]。

系统主要面向[用户角色1]和[用户角色2]，支持[平台1]和[平台2]访问。
```

**Web + 小程序双端描述要点**：
- 说明 Web 端（PC）主要面向哪类用户（通常是管理端/运营端）
- 说明微信小程序端面向哪类用户（通常是客户端/用户端）
- 说明两端的数据同步关系（共享后端 API，数据实时同步）

---

### 第二章 核心业务对象

**写作要点**：
- 每个核心业务实体独立一节
- 使用【】标记对象名称
- 所有字段用表格定义，不写段落描述
- 枚举类型字段需列出所有枚举值

**标准表格格式**：

**【对象名称】**

[1-2句说明该对象的业务含义和用途]

| 字段名称 | 字段说明 | 限制/规则 |
|----------|----------|----------|
| id | 主键标识 | 系统自动生成，唯一 |
| name | 名称 | 必填，最大长度50字符 |
| status | 状态 | 0:草稿 1:已发布 2:已下线 |
| createTime | 创建时间 | 系统自动记录，不可修改 |
| remark | 备注 | 可选，最大长度500字符 |

**常见业务对象示例**（根据实际项目调整）：

- Web 管理系统：【用户】【角色】【权限】【菜单】【操作日志】
- 电商类：【商品】【订单】【购物车】【优惠券】【支付记录】
- 管理类：【客户】【项目】【合同】【发票】【报表】
- 内容类：【文章】【分类】【标签】【评论】【附件】

**写作示例**（线索管理系统）：

**【销售线索】**

销售线索是指潜在客户的信息记录，记录从获取渠道、跟进状态到最终成交的全过程。

| 字段名称 | 字段说明 | 限制/规则 |
|----------|----------|----------|
| id | 线索主键 | 系统自动生成，全局唯一 |
| companyName | 客户公司名称 | 必填，最大长度100字符 |
| contactName | 联系人姓名 | 必填，最大长度50字符 |
| phone | 联系电话 | 必填，11位手机号 |
| source | 线索来源 | 1:官网 2:展会 3:转介绍 4:电话营销 5:其他 |
| status | 跟进状态 | 0:待分配 1:跟进中 2:已成单 3:已放弃 |
| assignedTo | 负责销售 | 关联【用户】，可为空表示未分配 |
| expectedAmount | 预计金额 | 可选，单位元，保留2位小数 |
| nextFollowTime | 下次跟进时间 | 可选，datetime 类型 |
| createTime | 创建时间 | 系统自动记录 |

### 第三章 功能模块设计

**写作要点**：
- 每个功能模块独立一节（3.1、3.2、3.3...）
- 每节包含5个固定子节
- 子节3.3字段说明必须使用表格

**标准模块模板**：

#### 3.X [模块名称]

##### 3.X.1 功能入口与页面说明

[说明本模块的菜单位置、URL路径，以及包含哪些子页面/功能页]

Web 端入口：[菜单路径，如"系统管理 > 用户管理"]
小程序端入口：[Tab页/首页卡片，如"我的 > 基本信息"]

本模块包含以下页面：
- [页面名称1]：[功能简述]
- [页面名称2]：[功能简述]

##### 3.X.2 展示说明

[描述列表页的展示规则]

**列表展示**：默认按[字段名]降序排列，每页显示[N]条记录，支持翻页。

**搜索条件**：

| 搜索项 | 类型 | 说明 |

| 关键词 | 文本输入 | 模糊匹配[字段A]、[字段B] |

| 时间范围 | 日期范围 | 按[时间字段]筛选 |

**列表列定义**：

| 列名 | 说明 |

| 字段名 | 说明 | 类型/限制 |

- 再用表格列出技术选型

### 第五章 接口说明

**写作要点**：
- 选取最重要的10-20个接口（每个模块1-3个代表性接口）
- 无需列出所有接口，优先选 POST/PUT 等写接口和核心查询接口
- 每个接口用完整的请求/响应表格定义

**标准接口模板**：

**[接口名称]（如：线索列表查询）**

| 属性 | 值 |
|------|---|
| 请求路径 | /api/clue/list |
| 请求方式 | GET |
| 接口说明 | 分页查询销售线索列表，支持多条件筛选 |

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| page | Integer | 是 | 当前页码，从1开始 |
| size | Integer | 是 | 每页条数，默认10 |
| keyword | String | 否 | 关键词，模糊搜索公司名/联系人 |
| status | Integer | 否 | 跟进状态，不传则查询全部 |
| startDate | String | 否 | 创建时间起，格式 yyyy-MM-dd |
| endDate | String | 否 | 创建时间止，格式 yyyy-MM-dd |

响应参数：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | Integer | 响应码，200表示成功 |
| message | String | 响应消息 |
| data.total | Long | 总记录数 |
| data.records | Array | 线索记录列表 |
| data.records[].id | Long | 线索ID |
| data.records[].companyName | String | 客户公司名称 |
| data.records[].status | Integer | 跟进状态 |

## 三、常见问题与写作建议

**Q：功能模块应包含多少个？**

通常 5-15 个模块。太少说明功能描述不完整，太多则重复冗余。建议按主菜单划分，每个一级菜单对应一个模块。

**Q：业务对象和功能模块字段重复怎么办？**

业务对象章节定义数据库层面的所有字段（含数据库字段），功能模块章节定义前端表单/列表层面的字段（可以是子集，用 UI 层面的名称）。两者关注点不同，适当重复是正常的。

**Q：接口说明需要多详细？**

选代表性接口，每个接口完整列出请求/响应参数即可。不要只列接口路径不写参数，也不需要列出所有接口。

**Q：Web 端和小程序端功能完全不同，如何组织？**

建议先描述后端共用功能（业务对象、核心接口），再分别描述 Web 端功能模块和小程序端功能模块，用"Web 端"/"小程序端"小节标题区分。

**Q：没有接口文档（Swagger）怎么办？**

直接从 Controller 代码中提取：读取 `@RequestMapping`、`@PostMapping` 等注解获取路径，读取 DTO 类获取参数，读取返回类型获取响应结构。AI 可自动完成这一过程。
